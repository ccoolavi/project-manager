## 📊 Architecture Summary

### Multi-Tenant Database Schema (12 tables)
```
users (authentication)
  ├─ organizations (multi-org workspaces)
  │   ├─ organization_members (RBAC mapping)
  │   ├─ projects (project grouping)
  │   │   └─ sub_projects (nested projects)
  │   │       └─ tasks (kanban tasks)
  │   │           └─ time_entries (time tracking)
  │   ├─ habits (habit tracking per user)
  │   ├─ kaizen_logs (improvement logs)
  │   ├─ organization_invites (member invites)
  │   ├─ audit_logs (compliance logging)
  └─ otp_sessions (2FA support)
```

### Authentication Flow
1. User registers/logs in → JWT generated with org_id + role + permissions
2. Frontend stores JWT in localStorage
3. Every API request includes `Authorization: Bearer {token}`
4. Server validates JWT and checks org membership + permissions
5. 401 on invalid token → Frontend redirects to login

### Role-Based Access Control (RBAC)
```
owner:   Full org control + delete org
admin:   Manage members, create/edit/delete projects & tasks
editor:  Edit projects, create/assign tasks
viewer:  Read-only access to projects & tasks
member:  Default - can view + create tasks
```
